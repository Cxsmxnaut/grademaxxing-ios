# Native implementation validation

Evidence collected October 11, 2026. This is a first implementation. Full Xcode 27.0 (build 27A266a) with the iOS 27.0 simulator runtime is now installed in this environment, so the native sources have been **built and executed on iPhone simulators**: the shared `Grademaxxing` scheme builds and all seven synthetic UI cases pass on a small and a large iPhone. That run found and fixed two defects, described below. Native sources also pass `xcrun swift-format lint --strict --recursive App Sources Tests UITests Package.swift`.

This standalone repository contains an exported copy of the native sources. The web test/build results below were collected in the parent Grademaxxing checkout, not a web application in this repository. ## Defects found and fixed by this run

1. **The app target built for a simulator slice that the local Swift package could not provide.** The generated project set no `ONLY_ACTIVE_ARCH`, so Debug builds compiled the app for both `arm64` and `x86_64` while the `GrademaxxingCore` package product was built for `arm64` only. The `x86_64` compile failed with `module file … is incompatible with this Swift compiler: built for incompatible target` and `Unable to resolve module dependency: 'GrademaxxingCore'`, failing both GitHub Actions runs (`Native iOS checks`, runs 38192021305 and 38192401393) as well as a local reproduction of the same command. `ios/scripts/generate-project.py` now sets `ONLY_ACTIVE_ARCH = YES` for Debug and `NO` for Release, matching Xcode's template default. Verified: before the change the app compiled `arm64` + `x86_64` and failed; after it the app compiles `arm64` only, with no `x86_64-apple-ios` slices, and the full suite reports `TEST SUCCEEDED`. The workflow itself has not been re-run because this repository was not pushed.
2. **The search field was unreachable on the three searchable screens.** With an inline navigation title, the iOS 27 default presentation created no search field at all: the captured accessibility hierarchy of the course screen contained no `SearchField`, no `TextField`, and no search button, so neither a user nor VoiceOver could reach assignment search. `ios/App/Theme.swift` now exposes `alwaysVisibleSearch(text:prompt:)`, which pins `.navigationBarDrawer(displayMode: .always)` on iOS and falls back to the default modifier elsewhere (the placement is unavailable on macOS, and the repository compiles every app source for macOS and Mac Catalyst). `CourseView`, `DocumentsView`, and `MailView` use it, and the UI cases now assert the returned search field on all three screens.

The planner inclusion case previously tapped the center of a `Toggle` row, which does not move the switch; it now asserts the switch value and taps the control itself. The period/search case now submits the query to dismiss the keyboard and scrolls to the filtered row, because a lazy `List` does not realize rows that are off screen.

## What remains unverified

- **Native visual QA:** No screen was inspected by eye. Dark/light appearance, Dynamic Type sizes, layout on each device class, keyboard dismissal behaviour, and VoiceOver output remain unverified; the simulator runs assert state and identifiers, not appearance.
- **Background and lifecycle:** Background/resume, timeout, offline mode, app-switcher privacy shielding, and account switching have not been exercised.
- **Keychain and file protection:** The automated session tests use an in-memory vault and synthetic transport. On-simulator Keychain storage, device-only protection, and Quick Look preview rendering under file protection remain unverified.
- **Live school integration:** No designated account was provided or authorized. No live sign-in, portal read, student record capture, or real credential operation was performed.
- **Native CI:** The arch fix is verified locally with the same scheme, configuration, and command the workflow runs, but the workflow has not been re-executed. Two test runs also hit a transient XCTest runner bootstrap failure (`Early unexpected exit … handleStalledWait`) that cleared after shutting the simulators down; it did not reproduce in the runs recorded above.
- **Distribution:** Signing team, final icon, full privacy disclosures, feature parity, and TestFlight/App Store review remain on the roadmap. The privacy manifest is a scaffold and must be reconciled before distribution.
- **Physical device:** Nothing in this document is physical-device evidence. A passing simulator run does not establish on-device behaviour, signing, or performance.

The first failure of `swift test` established that Command Line Tools lacks Apple's Testing module. The check suite uses `swift run GrademaxxingChecks` and has no dependency on XCTest, Swift Testing, or external packages.
